## Trust boundaries

1. Browser-to-application traffic is HTTPS only in production.
2. Tenant context and object authorization are resolved on the server; client-provided tenant IDs are not trusted.
3. Application-to-database, cache, object storage and suppliers use separate least-privilege service identities.
4. Export and download authorization is evaluated both when an artifact is generated and when it is retrieved.
5. Supplier failure or revocation enters an exception workflow; it never broadens access or falls back to public storage.
6. A generic role or caller-provided council status cannot cross the regulated-capability boundary; the server must resolve current professional and clinic evidence from trusted records.
7. Psychology Council inspection or orientation access is an exceptional, purpose-bound disclosure: scope, authority, actor, records disclosed and outcome are documented without granting standing tenant access.
8. Psychological records, patient self-reports and restricted assessment material remain distinct authorization and export domains even when they concern the same person.
